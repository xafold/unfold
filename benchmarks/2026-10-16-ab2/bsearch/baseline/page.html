How binary search finds a number

Binary search looks for a value in a sorted array. Each comparison throws away half of the values that are left. That is why it needs about log2(n) steps, not n.

The idea uses two indexes. lo is the first index that can still hold the target. hi is the last one. We look at the middle element, mid. The array is sorted, so one comparison tells us which half the target must be in. We drop the other half and repeat.

Candidates left after each comparison

Why about log2(n) steps?

Start with n candidates. After one comparison, at most n/2 are left. After two, at most n/4. After k comparisons, at most n/2k are left.

The search must stop when no candidates are left. So it can run only while n/2k ≥ 1, which means k ≤ log2(n). Add the last comparison and you get the worst case:

comparisons ≤ ⌊log2 n⌋ + 1

For the 32 values above, that is ⌊log2 32⌋ + 1 = 6. Try a target that is bigger than every value, such as 200. It takes exactly 6 comparisons.

Doubling n adds only one comparison. A billion sorted values need at most 30.

One rule matters: the array must be sorted. Without order, a single comparison tells you nothing about the other values, and you must check them all.
