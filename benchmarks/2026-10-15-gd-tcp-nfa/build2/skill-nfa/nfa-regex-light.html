Sets, backtracking and DFAs

Real engines use one of three ways to handle the choices in an NFA. For this regex, subset construction gives 4 DFA states plus an empty dead state: {0} {1,2,3,4,6} {1,2,3,4,5,6} {7}.

ApproachHow it handles a choiceTime for n symbols, m statesUsed by
Set simulation (this figure)keeps every choice in S at onceO(n·m)RE2, Go regexp, Rust regex (one of its engines)
Backtrackingtries one path, and goes back to the last choice if it failsexponential for some patterns, for example (a*)*bPCRE, Perl, Python re, JavaScript, Java
DFA (subset construction)turns each reachable set into one state before it reads inputO(n), but up to 2m stateslex and flex; grep and RE2 build DFA states as needed

What the figure leaves out

Left outWhat really happens
SearchThe figure checks the whole input. To find a match inside a longer text, the engine adds state 0 to S before each symbol.
Capture groupsA Pike VM keeps the start and end of each group next to each state in S. The figure keeps only the states.
Backreferences(a)\1 needs to remember text, which no finite set of states can do. Only backtracking engines support it.
Order of ε edgesThe order does not change match or no match. It only decides which submatch an engine reports.
