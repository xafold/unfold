What the figure leaves out

  • Optimized builds. With gcc -O2, main holds the constant 25 and never calls sum_sq: the compiler inlined both calls and did the arithmetic (checked). JIT compilers in the JVM and V8 also inline small hot functions.
  • The return address. In machine code, call pushes the address of the next instruction and ret pops it and jumps there. A virtual machine keeps the same thing in its frame. The figure shows it as "waits at line N".
  • Methods. obj.f(x) first finds which f to run (a vtable in C++ and Java, an inline cache in V8, CPython and YARV). Then it is a call like this one, with the object as a hidden first argument (this or self).
  • Closures. A function that uses a variable of an outer function keeps that variable alive after the outer frame is removed, so the runtime keeps it outside the stack. V8's LdaImmutableCurrentContextSlot in scene 6 reads square from such a context.
  • Exceptions. A throw removes frames from the top until a frame has a handler. The recursive functions measured in scene 7 catch RecursionError, RangeError, SystemStackError and StackOverflowError this way. C and Rust cannot catch a stack overflow.
  • async functions and generators. Their frame can pause, live on the heap, and continue later. It is not removed when the function first gives control back.

Words used here

  • Parameter: the name in the definition (x, a, b). Argument: the value passed in the call (3, 4).
  • Frame (activation record): one call's parameters, local variables and the place to continue in the caller.
  • Call stack: the frames of the calls that have not returned yet. Only the top frame runs.
  • Calling convention (ABI): the rule for where arguments and results go (registers or the stack), so that code from different compilers can call each other.
  • Stack overflow: no room for the next frame. Scene 7 shows where each language stops.
