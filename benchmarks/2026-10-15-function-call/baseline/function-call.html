The idea in five steps

A function call stops the current code, runs other code, and then continues exactly where it stopped. Every language does the same five things. They differ only in how they do them.

  1. Evaluate the arguments. The caller computes each argument value. Most languages do this before the call. Haskell waits until a value is needed.
  2. Save the return address. This is the place in the caller where execution must continue after the call.
  3. Push a new frame. A frame is a block of memory for one single call. It holds the parameters, the local variables, and the return address.
  4. Run the body. The callee (the called function) runs. If it calls another function, another frame goes on top.
  5. Return and pop. The callee puts the result where the caller expects it. Its frame is removed. Execution continues at the return address.

Why a stack?

Last in, first out

The function that was called last always finishes first. A stack has exactly this order. A call and a return each only move one pointer, so they are very cheap.

Recursion works

Each call gets its own frame. So a function that calls itself has a separate x for each call. The calls do not overwrite each other's variables.

Stack overflow

The stack has a fixed maximum size. If calls nest too deep, for example in recursion without an end, it runs out of space. That error is a stack overflow.

On x86-64 the stack grows down, toward lower addresses. The register rsp always points to the top.

On Linux and macOS (System V ABI), the first six integer arguments are passed in registers rdi, rsi, rdx, rcx, r8, r9. Only extra arguments go on the stack. The result comes back in rax.

Windows x64 uses a different convention: rcx, rdx, r8, r9, plus 32 bytes of "shadow space" that the caller reserves.

Small functions often keep everything in registers. Then their frame is only the return address.

Three ways languages run a call

Native machine code

C, C++, Rust, Go, Swift. The compiler turns the call into a call instruction. The CPU's own stack holds the frames. This is the fastest kind of call. Compilers often inline small functions, which means they copy the body into the caller so no call happens.

Virtual machine

Java, Kotlin, C#, Python, JavaScript, Ruby, PHP. The source becomes bytecode. A call is one bytecode instruction, and the VM builds the frame in its own data structures. A JIT compiler (Java, Kotlin, C#, JavaScript, and optionally Ruby and PHP) turns hot code into native calls at runtime.

Lazy evaluation

Haskell. A call does not run at once. It makes a thunk: a stored "compute this later" note on the heap. The thunk runs only when something needs its value. Frames on the stack say what to do with a result when it arrives.
